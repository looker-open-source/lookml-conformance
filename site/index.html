Open, vendor-neutral conformance suite for LookML

One open test suite for how LookML resolves. So every tool can read it the way Looker does.

LookML is Looker's semantic modeling language: it defines the dimensions, measures and relationships behind the metrics an organization reports on. Data catalogs and lineage tools read it straight from git, and AI assistants increasingly answer questions through it, so each of them has to reproduce how Looker resolves a project. lookml-conformance makes that behavior explicit and testable: 39 minimal LookML projects, each tied to a quoted rule, run against the open-source tools that build catalogs and lineage from LookML.

Why it matters

Lineage is only as right as the LookML resolution behind it

Looker assembles each model from its includes, applies refinements in include order and merges extends. Each step can change which table a view reads, so every tool that builds lineage from LookML has to reimplement all of them, usually without a Looker instance to check against. These are the areas where tools and Looker differ most today.

Method

Every expectation is traceable

  1. 1

    One rule

    A case states a single rule in one sentence, such as "the file included last wins".

  2. 2

    A verbatim quote

    The rule cites the Looker documentation word for word, linked to the section. check-citations re-reads every page and fails if a quote changes.

  3. 3

    A minimal project

    A few lines of LookML that isolate the rule, and the resolution Looker produces for each model.

  4. 4

    An honest adapter

    Each tool runs through an adapter that reports what the tool produces and never fills a gap the tool leaves.

How to read the results

Conformance is hard, and lineage on top of it is harder. The tools scored here are maintained by people solving a difficult problem, mostly without access to Looker's own resolver. The scores describe the released versions pinned in adapters.json and are a snapshot, not a ranking. Every difference comes with a minimal project that reproduces it, so it can serve directly as a test case for a fix.

If a case or an adapter misrepresents what a tool does, that is a bug in this suite. Please open an issue.

Run it

Score your tool or your branch

An adapter runs your tool on LookML projects and prints one JSON line per project. In Python that is one class with one method. Point the runner at your branch and use the exit status as a CI gate.

Write an adapter 
# reproduce the published scorecard
pip install -e .
lookml-conformance setup
lookml-conformance run

# score a branch you have installed
lookml-conformance run \
  --command "python -m lookml_conformance.adapters.datahub" \
  --name datahub-branch

# add a tool
lookml-conformance new-adapter my-tool
lookml-conformance check-adapter --command "python my_tool.py"
