Conformance suite for LookML tools

Lineage tools read LookML. Most read it differently from Looker.

Minimal LookML projects, each tied to a rule quoted from the Looker documentation, run against the tools that build catalogs and lineage from LookML.

See the results Test your tool

Why it matters

Lineage is only as right as the LookML resolution behind it

Looker assembles each model from its includes, applies refinements in include order and merges extends. A tool that skips a step reports a table Looker never queries, and the catalog looks complete while being wrong.

Method

Every expectation is traceable

  1. 1

    One rule

    A case states a single rule in one sentence, such as "the file included last wins".

  2. 2

    A verbatim quote

    The rule cites the Looker documentation word for word, linked to the section. check-citations re-reads every page and fails if a quote changes.

  3. 3

    A minimal project

    A few lines of LookML that isolate the rule, and the resolution Looker produces for each model.

  4. 4

    An honest adapter

    Each tool runs through an adapter that reports what the tool produces and never fills a gap the tool leaves.

Run it

Score your tool or your branch

An adapter is any command that takes a project directory and prints one JSON line. Point the runner at your branch and use the exit status as a CI gate.

Read the docs 
# reproduce the published scorecard
pip install -e .
lookml-conformance setup
lookml-conformance run

# score a branch you have installed
lookml-conformance run \
  --command "python -m lookml_conformance.adapters.datahub" \
  --name datahub-branch
